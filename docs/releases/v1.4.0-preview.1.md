# RF 스위퍼 v1.4.0-preview.1

이름 없는 BLE 광고와 비콘, 같은 주소의 반복 광고를 다시 확인할 수 있도록 광고별 원본 기록을 추가했습니다. Android가 앱에 전달하지 않은 신호까지 모두 수신한다는 보장은 하지 않습니다.

## 달라진 점

- **광고별 기록:** 현재 BLE 탐색에 전달된 결과마다 원본 바이트·주소·시각·신호 세기·잘림 상태를 앱 내부 SQLite에 저장합니다. 같은 주소·내용의 반복 광고도 앱에서 중복 제거하지 않습니다. 이름이나 제조사, 지원하는 비콘 형식이 없어도 기록 대상입니다.
- **비콘 형식:** iBeacon 호환·AltBeacon·Eddystone UID/URL/TLM/암호화 TLM/EID를 표시합니다. 같은 주소가 한 탐색에서 보낸 여러 형식도 보존합니다. 형식은 하드웨어 제조사·모델을 보증하지 않습니다.
- **저장 상태:** 수신 화면에서 앱에 전달된 횟수와 저장 완료·대기·실패를 구분합니다. 대기열 초과·저장 오류를 숨기지 않습니다. 정상 중지 후 접수한 행은 순서대로 저장하며, 강제 종료 시 아직 쓰지 못한 행은 유실될 수 있습니다.
- **불확실한 결과 보존:** 시각 검증에 실패하거나 해석하지 못한 광고도 원본과 사유를 남깁니다. 이런 시각을 비교 화면의 관측 시간으로 만들어 사용하지 않습니다. 잘못된 RSSI도 원본에는 남기고 거리 계산에서는 제외합니다.
- **오류 복구:** 일시적인 BLE 등록·내부·자원 오류는 지연 재시도합니다. 과도한 탐색 요청 오류는 더 오래 기다립니다. 건강한 탐색이나 단순히 광고가 없는 상태에서는 탐색을 반복 재시작하지 않습니다. 교대·중지·재시도 상태도 기록합니다.
- **원본 내보내기:** 모든 실제 탐색 세션을 JSONL로 저장할 수 있습니다. 느린 파일 출력과 신규 광고 쓰기를 분리했습니다. 내보내는 파일에는 알려진 저장 실패와 정상 종료 여부도 포함합니다.

## 사용 순서

1. 비교 탭에서 공간 이름을 정하고 **실제 탐색 → 탐색 시작**을 누릅니다. 실제 탐색의 공간 이름은 시작할 때 고정됩니다.
2. 짧은 광고·비콘을 우선 관측하려면 수신 탭에서 **BLE 우선**을 유지합니다. 범위 확장은 일반 Bluetooth 검색 중 BLE를 잠시 중지합니다.
3. **BLE 광고 기록**의 전달·저장 완료·대기·실패를 확인하고, 장비 상세의 **무선 정보 자세히**에서 비콘 형식을 확인합니다.
4. 필요하면 **BLE 광고 기록 파일로 저장**을 누릅니다. 파일 선택기로 앱을 벗어나면 탐색이 중지되므로 복귀 후 다시 시작하세요. 주소별 스냅샷 보고서와 광고별 JSONL은 별도의 기록입니다.

## 파일·검증

- `rf-sweeper-v1.4.0-preview.1-debug.apk`: Android 10 이상, 기존 프리뷰와 같은 debug 서명 테스트용 APK.
- `SHA256SUMS.txt`: APK 확인값. `QUICKSTART.ko.md`와 PNG는 가상 입력으로 만든 실제 UI 예시입니다.
- JUnit·Robolectric 테스트 **310개 통과**(실패·오류·건너뜀 0), APK 빌드 통과, Lint 오류 0개·경고 21개. 이름 없는 광고 300회와 시각 미확정 1회의 개별 기록·복원, 비콘 형식, 대기열 초과·쓰기 실패, 느린 내보내기 중 기록 지속, 오류 복구와 중지 콜백을 검증했습니다.

**개인정보 변경:** 이번 버전부터 BLE 광고 원본을 별도 보관하므로 광고에 든 비콘 식별자·서비스 데이터·이름 등이 기록될 수 있습니다. 자동 익명화·추가 암호화는 없으며 Android 백업 정책도 적용될 수 있습니다. 공유 전에 내용을 확인하세요. 통신 내용 감청·페어링·연결·전파 방해 기능은 없습니다.

실물 단말의 비콘 수신률·누락률·배터리·발열은 아직 검증하지 않았습니다. 일반 Android 탐색은 무선 대역 전체를 기록하는 수신기가 아니며, 지원 범위·거리·전파 충돌·운영체제 제한·앱 중지로 광고를 놓칠 수 있습니다. `앱에 전달` 수치는 실제 전파의 총 송신 횟수나 탐지 성공률이 아닙니다.
