# RF 스위퍼 v1.3.0-preview.1

입실 전 환경을 저장한 뒤 새로 관측된 주소·Wi-Fi 채널·숨김 SSID 이력을 비교하는 Android 프리뷰입니다. 이번 버전은 공개 API로 확인할 수 있는 탐색 종류를 넓히고, 직접 수신한 신호와 시스템이 제공한 목록·환경 정보를 구분합니다.

## 달라진 점

- **Wi-Fi 채널 변화:** 2.4·5·6 GHz의 관측 채널, AP 수와 신호 세기 분포, 기준에 없던 채널, 같은 AP의 채널 변경을 표시합니다. 실제 트래픽 혼잡률이나 간섭량 측정은 아닙니다.
- **숨김 SSID 이력:** 이름이 보이지 않은 AP를 필터링하고, 나중에 이름이 보여도 과거 숨김 기록을 유지합니다. 한 번 포착된 채널·주소는 사라져도 보존합니다. 숨김만으로 위험을 판정하지 않습니다.
- **BLE 수신 정보 확장:** 지원 단말에서 기본·확장 광고, 서비스 UUID, PHY, 연결 가능 광고 여부를 기록합니다. 확장 설정 실패 시 기본 광고로 전환하고 상태를 알립니다.
- **범위 확장 선택:** BLE 45초와 일반 Bluetooth 탐색 최대 16초를 교대로 실행합니다. 실제 검색 종료가 확인되기 전에는 BLE를 재개하지 않습니다. 일반 Bluetooth는 검색 가능한 기기에 한정됩니다.
- **Wi-Fi Direct 목록:** 60초 간격으로 발견을 요청합니다. OS 캐시일 수 있으므로 목록 첫 확인만 기록하며 RSSI·거리·연속 수신·재등장을 만들어 표시하지 않습니다.
- **기지국 환경 참고:** 기본 SIM 모뎀의 LTE·NR 등 기지국 정보를 별도 조회·저장합니다. 주변 휴대전화 목록이 아니며 추가 장비 수·합집합·경보에서 제외합니다.
- **비교 조건 보존:** 스냅샷에 요청한 탐색 종류를 저장합니다. 기준보다 범위를 넓혔다면 해당 종류를 입실 전에 탐색하지 않았음을 알립니다.
- **상세·내보내기:** Android가 제공한 Wi-Fi 채널 폭·보안/기능 광고와 Bluetooth 메타데이터, 기지국 환경을 펼쳐 보고 텍스트 보고서로 저장할 수 있습니다. 이전 v1·v2 저장 자료도 읽습니다.

## 사용 순서

1. 수신 화면에서 `BLE 우선` 또는 `범위 확장`을 선택하고 탐색을 시작합니다. 이어폰의 짧은 BLE 광고를 우선 관측할 때는 BLE 우선을 유지합니다.
2. 빈 시험실에서 충분히 관측한 뒤 `입실 전 저장`을 누릅니다. 확장 모드라면 Bluetooth 교대와 Wi-Fi 조회 결과까지 확인합니다.
3. 같은 공간·같은 탐색 범위를 유지하며 입실 후와 시험 중 비교합니다.
4. `추가` 또는 `전체 이력`에서 유형·제조사/모델 후보·관측 시각을 확인하고, `채널`에서 새 채널과 숨김 이력 AP를 확인합니다.

## 첨부·검증

- `rf-sweeper-v1.3.0-preview.1-debug.apk`: Android 10 이상, 기존 프리뷰와 같은 **debug 서명 테스트용 APK**입니다.
- `SHA256SUMS.txt`: APK SHA-256 체크섬.
- `QUICKSTART.ko.md`, 채널·확장 탐색 PNG: 실제 Compose 화면을 가상 데이터로 실행한 사용 예시입니다.
- JUnit·Robolectric 단위/Android UI 테스트 241개 통과(실패·오류·건너뜀 0), APK 빌드 통과, Lint 오류 0개·경고 21개.

실물 단말의 무선 수신·배터리·발열 검증은 아직 수행하지 않았습니다. 화면 갱신이 빨라도 Android의 Wi-Fi 조회 제한이나 무선 하드웨어의 누락을 없애지는 못합니다. 통신 내용 감청·연결·페어링·전파 방해는 수행하지 않습니다. 광고/발견 응답이 없는 기기와 임의 주파수 송신기를 모두 찾는 스펙트럼 분석기는 아닙니다. 추가 주소·숨김 SSID·기지국 변화는 부정행위의 증거가 아닙니다.
